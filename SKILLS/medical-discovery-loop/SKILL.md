# 医疗发现流水线（Medical Discovery Loop）· 通用模板

持续寻找治疗方案 / 医疗发现的可复用流程。设计原则：**每天可跑、无人值守可跑、创新与实证并重**。

> ⚠️ **隐私声明**：本模板不含任何真实患者数据。所有 `<PLACEHOLDER>` 必须由使用者
> 用【自己患者的】信息替换；共享此模板时不得附带真实病历、基因报告或用药反应记录。

## 触发词
"跑一轮发现" / "医疗发现" / "继续找方案" / "有新药或新机制吗" / "一直找方案" / "自动化研究"

## 输入（每次必读，防漏）
1. `<YOUR_FACTSHEET>`（开局必读底稿：患者分子画像、诊断、已确立事实）
2. 数据库 `<YOUR_DB>`（可换成任意你信任的知识库）：
   - `kb_facts` 表（已确立事实，最新 fid 为准）
   - `response` 表（**干预史过滤器**：已验证失败 / 负效应 / 无效清单）
   - `behavior_obs` 表（最新行为观察）

## 硬约束（红线，任何候选不得违反）
- **<患者基因红线 1，例如某代谢酶慢代谢基因型>**：禁推会放大该通路毒性的干预。
- **干预史过滤器**：与 `response` 表交叉，同机制假说自动降级 / 标注"曾试失败"。
- **<患者生化红线，例如某代谢物偏高需限量>**：对应底物限量。
- **<患者兴奋/抑制失衡红线，例如兴奋性氨基酸偏高>**：禁升该递质。
- **<患者年龄/体重> 儿童安全**；任何新干预标注需医生评估。

> 红线必须从【你自己的】基因报告 + 生化 + 干预史提取，不要用别人的红线套自己的患者。

## 流水线步骤
1. **读底稿 + 干预史**（见上）
2. **全领域机制扫描**：派 1 个 reasoning 智能体（Agent, model=reasoning），WebSearch 最近
   1–2 周 PubMed / ClinicalTrials / 中文源，方向不限：神经发育 / 代谢 / 肠道 / 免疫 /
   表观遗传 / 线粒体 / 炎症 / 营养 / 物理干预。prompt 必须注入：患者分子画像 +
   **完整干预史（`response` 表）** + 红线（缺一不可）。
3. **过滤**：新发现 × 干预史交叉（同机制 → 降级）；× 红线（违规 → 淘汰）。
4. **机制推理**：每条给 靶点 → 机制 → 契合度 → 风险 → 验证标志物 → 评级（A 值得下注 / B 观察 / C 不投入）。
5. **落库**：`kb_facts` 新增（cat='discovery'，subject=发现名，value=完整推理）。
6. **追加发现日志**：`<YOUR_DISCOVERY_LOG>`（日期 / 来源 / 发现 / 契合度 / 评级 / 是否新方向）。
7. **汇报**：仅当出现"库内未记录 + 机制契合 + 非已证伪类"的高价值新方向时，写醒目总结给用户；
   否则一句话"本轮无新增高价值发现（已扫描 N 条，过滤 M 条）"。
8. 追加当日工作日志 `<YOUR_MEMORY_LOG>`。

## 输出格式（发现条目）
```
## YYYY-MM-DD | 来源 | 评级
- 发现/候选：
- 靶点→机制：
- 患者契合度（基因/临床）：
- 风险与红线检查：
- 验证方式：
- 与干预史关系（是否曾试失败）：
```

## 注意
- 每轮控制 token：1 个 reasoning 智能体即可（单强智能体优先）。
- 已证伪方向不再重复投入研究资源（除非出现全新机制证据）。
- 发现日志只增不删；知识库为权威真相源（.md 记忆文件可能被会话重置）。
- **所有医学结论必须标注"决策支持、非处方建议，需临床/遗传医生裁决"。**
