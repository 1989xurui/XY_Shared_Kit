# 多智能体文献/证据综合范式

## 何时用
- 用户要求"全网检索 + 结合我们已有信息 + 多智能体 + 先总结信息权重"。
- 任何需要"内部已知事实(权重化) + 外部检索证据"交叉验证后才能下结论的任务。

## 标准流程（严格按顺序）
1. **抽取自家地基**：从项目数据库/笔记/报告中，用 SQL 或读取，抽出核心事实。不要凭记忆——落到具体数值（基因、剂量、评分、日期）。
2. **构建"信息权重关系"简报**：把抽出的事实分级（🔴最高/🟠中/🟡低/⚪空白窗/🎯目标），并明确每条对方案的意义。这是给检索智能体的统一上下文，必须自包含（智能体看不到你的数据库）。
3. **并行派 4 个检索智能体**（单次消息发多个 Agent 调用）：
   - 智能体A：英文机制药/新型疗法（latest RCT/指南，含证据等级）
   - 智能体B：中文文献 + 真实世界病例（相似表型个案、老药新用、指南共识）
   - 智能体C：老药新用 + 选药匹配（在"不破核心禁忌"前提下找兼容候选）
   - 智能体D：对应用药审计（构建适配矩阵，指出已试药物的失败是否对应已知药理/基因画像，并给出阶梯偏离点）
   - 每个智能体 prompt 必须内嵌步骤2的简报全文 + 明确返回格式（表格+TopN+链接，限 ~700 词）。
4. **合成报告**：整合收敛共识 + 必须诚实的方法学校正（外部智能体常指出内部"红线/禁忌"机制标签不精确，如 X 连锁半合子非 +/+、CPIC 无可操作等级、某 HLA 仅限某单药）——这类校正要显式呈现并标注"需临床/专家裁决"，不可默默覆盖用户既定框架。
5. **目标罗盘**：用户若给定恢复/商业/技术指标目标，把它设为所有方案的评估 compass，明确"单点手段达不到目标，主干干预是什么"。
6. **入库 + 免责**：生成 HTML 报告写入项目目录并登记 report 表；医学类必须附方法学与免责声明（决策支持非处方建议）。

## 关键坑（本范式踩过）
- **智能体无数据库访问权**：简报必须自包含，含具体数值，否则检索偏。
- **f-string 引号陷阱**：报告生成脚本里不要在 f-string 内嵌 `\"` 或混用引号，改用 `.replace("__TOKEN__", val)` 注入动态值最稳。
- **权重先行**：先写权重简报再派agent，否则检索无锚点、结论发散。
- **诚实优于迎合**：外部证据与用户内部框架冲突时，呈现冲突+留裁决口，不替用户做不可逆判定。

## 输出物
- `xy_<topic>_report.html`：权重表 + 共识 + 治疗/方案映射表 + 方法学校正 + 路线图 + 免责。
- 同时更新工作记忆日志。
