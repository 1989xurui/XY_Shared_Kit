# research-agent-landscape-analyzer

## 触发条件

用户满足以下任一：
- 发来科研智能体榜单/截图/表格，问“能不能调用/学习/接入”
- 问“XX 和 YY 科研 Agent 哪个开放”
- 要求对比多个 AI for Science 平台的可接入性

## 执行步骤

### Step 1. 提取列表
从用户输入（图片/OCR/文本）中读取每个智能体的：
- 企业/机构名
- 智能体名
- 应用场景/赛道

### Step 2. 批量检索每个智能体
对每个智能体，并行检索以下信息：
1. **官方网站 / 平台入口**
2. **是否开放 API / MCP server / Python SDK / CLI**
3. **是否开源（GitHub、License）**
4. **是否有技术论文 / 技术博客 / 白皮书**
5. **商业模式（免费、邀请制、企业授权、项目制代工）**

检索关键词模板（中英文）：
- `<智能体名> API MCP 开放平台`
- `<智能体名> GitHub open source license`
- `<智能体名> arxiv paper 论文`
- `<企业名> <智能体名> 官网`

### Step 3. 调用 WorkBuddy 推荐市场检索
使用 `workbuddy_marketplace_skill` 以 `search` action 检索相关 keyword，确认是否有官方 Skill。通常不会命中，但必须检查。

### Step 4. 分类
将每个智能体归入以下四档之一：
- **可直接调用**：有公开 API / 开源可部署 / MCP server，无需商务授权即可接入。
- **有条件调用**：有 API 或 MCP 形态，但需企业授权、联盟申请、邀请码、付费额度。
- **只能学习**：有论文/博客/开源模型/公开结果，但系统本身不对外提供可编程接口。
- **不可触及**：仅新闻稿/官网/会议报告，无 API、无开源、无论文，需采购硬件或签约合作。

### Step 5. 生成报告
生成深色主题 HTML 报告，包含：
- 核心结论（几档分布）
- 15 行详细表格（企业、智能体、场景、可调用性、可学习性、关键路径、证据链接）
- WorkBuddy 接入路径说明
- 对当前项目的直接意义（如适用）
- 接入优先顺序建议
- 诚实边界声明

报告路径建议：`C:/HY3/<topic>_agents_analysis_YYYY-MM-DD.html`，沿用项目深色 CSS。

### Step 6. 写工作日志
在 `C:/HY3/.workbuddy/memory/YYYY-MM-DD.md` 记录：输入来源、分类数量、关键发现、交付文件路径。

## 注意事项

- **不要假设所有科研智能体都可调用**。国内头部科研智能体多为平台/装置/企业授权制，真正“装上就用”的很少。
- **区分“平台”和“API”**。有网页入口 ≠ 可程序化调用。
- **区分“开源模型”和“开源系统”**。模型权重开源 ≠ 智能体系统可调用。
- **命名歧义要标注**。例如“DeepChem”同时指北京深云智合平台和美国的开源 deepchem 库，必须说明。
- **WorkBuddy 推荐市场通常没有官方 Skill**，但不能跳过检查。

## 示例输出格式

```
核心结论：15 个科研智能体中，可直接调用 X 个，有条件调用 Y 个，只能学习 Z 个，不可触及 W 个。

| # | 企业 | 智能体 | 应用场景 | 可调用性 | 可学习性 | 关键路径 |
```
